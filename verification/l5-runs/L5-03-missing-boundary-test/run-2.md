## チェックリスト判定

| 項目 | 判定 | 理由 |
|---|---|---|
| 境界値 | **該当** | 閾値 `MEMBER_DISCOUNT_MIN_PRICE`（=1000）の「ちょうど・すぐ下・すぐ上」3 本がまとめて削除された。下記の指摘を参照 |
| 異常系（null / 空 / 型不正 / 上限超過） | 非該当 | 差分はテスト削除のみで入力検証の経路に触れていない。`0 円` のケースは残存している |
| 権限（Controller の Guard） | 非該当 | Controller / Guard / 認可経路に差分なし |
| 冪等性 | 非該当 | `applyDiscount` は副作用のない純関数で、2 回呼んでも状態が変わらない |
| 並行性 | 非該当 | 共有状態・更新処理に差分なし |
| 障害時（外部サービス） | 非該当 | 外部呼び出しを含まないモジュール |
| トランザクション境界 | 非該当 | 複数テーブル更新に差分なし |
| N+1 | 非該当 | ORM クエリに差分なし |

## 指摘

| 重大度 | ファイル:行 | 指摘 | 根拠 |
|---|---|---|---|
| 高 | `apps/api/src/discount/discount.spec.ts:9-20`（削除箇所） | 会員割引の閾値境界（1000 ちょうど / 999 / 1001）を検証する example テスト 3 本が削除され、`discount.ts:13` の `if (price < MEMBER_DISCOUNT_MIN_PRICE)` を固定するテストが 1 本も残っていない | 削除後に残る assertion は `f(2000,false)=2000` / `f(1005,true)=904` / `f(0,true)=0` の 3 本と property 3 本のみ。**閾値ガードを丸ごと削除した実装**（`isMember` なら常に `floor(price*0.9)`）でも、`f(0,true)=floor(0)=0`・`f(1005,true)=904` が成立し全て緑になる。**`<` を `<=` に変えたオフバイワン**でも `1005>1000` のため 904 のまま緑になる。property 側も「割引後 ≤ 元価格」「非負整数」「非会員は不変」で、どちらの変異も満たしてしまう。削除された 3 本なら `f(999,true)=899≠999`（ガード削除）と `f(1000,true)=1000≠900`（`<=` 化）で検出できていた |

## 補足

この差分は検証ケース `L5-03-missing-boundary-test` が意図的に注入した欠陥であり、上記 1 件を挙げることが L5 ゲートの期待動作です。指摘は「テストが減った」という形式的な観察ではなく、**残存テスト群が閾値分岐を一切固定できていない**という実質を根拠にしています。

なお削除に伴う `MEMBER_DISCOUNT_MIN_PRICE` の import も同時に除去されており、未使用 import による lint 破綻はありません（この差分では L1 が反応しない、という点でも整合しています）。
